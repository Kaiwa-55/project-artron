# ข้อกำหนด Visibility และ Collision 3D

สถานะเอกสาร: ข้อกำหนดหลักสำหรับระบบใหม่  

สถานะ implementation: เพิ่ม `combat/vision/visibility_query_3d.gd` และเชื่อม MapRules แล้ว
ใช้ข้อมูลความสูงและ eye_offset ของ Combatant; ยกเลิกข้อยกเว้น same-surface ในโลก 3D
บันไดใช้ผิวลาดสำหรับ Collision เพื่อเปิดพื้นที่ด้านล่าง
กด F8 ใน Combat เพื่อเปิดเส้น Debug ของตัวที่เลือก (เขียวผ่าน/แดงถูกบัง)
ผล Query มีข้อมูล Collider และชนิดสำหรับตรวจสอบผ่าน debugger
ยังต้องทำ UI เลือกคู่ทดสอบอิสระและป้ายรายละเอียด Ray, ข้อมูลประตู และการตั้งค่าความสูงรายชนิดในเครื่องมือสร้างตัวละคร
Cover LIGHT/HEAVY เป็นข้อมูลผล Query; PARTIAL ใช้ค่าปรับ -4 เดิม ยังไม่เพิ่มกฎโบนัส Cover ใหม่
ขอบเขต: Combat ก่อน แล้วจึงใช้ร่วมกับ Exploration  
หลักสำคัญ: โลก 3D เป็นแหล่งข้อมูลจริงเพียงชุดเดียว ส่วน PNG และกล้องเป็นเพียงการนำเสนอ

## 1. เป้าหมาย

ระบบต้องรองรับ:

- อาคารหลายชั้นและตัวละครที่อยู่คนละระดับความสูง
- พื้น กำแพง ประตู ช่องเปิด บันได ทางลาด ราว และ Invisible Wall
- การมองผ่านช่องเปิดและการมองหรือยิงขึ้นลง
- การยืนใต้บันได เดินบนบันได และยืนเหนือพื้นที่อีกชั้น
- การแสดงศัตรู การเลือกเป้าหมาย การโจมตี AI และ Reaction ด้วยผลลัพธ์ชุดเดียวกัน
- การเพิ่มแผนที่ใหม่โดยไม่ต้องเพิ่มเงื่อนไขเฉพาะชื่อแผนที่หรือ `surface_id`

ระบบไม่ใช้เงา 2D, รูป PNG, ชั้นที่ผู้เล่นเลือกดู หรือระยะบนหน้าจอเป็นตัวตัดสิน Line of Sight

## 2. หน่วยและระบบพิกัด

- ข้อมูลกติกาทั้งหมดใช้หน่วยฟุต
- แกน `Y` คือความสูง
- `world_position` ของ Combatant คือตำแหน่ง 3D จริง ณ เวลาที่ใช้คำนวณ
- ตำแหน่งภาพ Animation ต้องไม่ถูกใช้แทนตำแหน่งกติกา
- ระหว่าง Animation การเดิน ระบบต้องเลือกให้ชัดว่าจะคำนวณจากตำแหน่งต้นทาง ตำแหน่งปลายทาง หรือจุดปัจจุบันบนเส้นทาง ห้ามผสมกัน
- ค่าเริ่มต้นสำหรับ Combat แบบผลลัพธ์ทันที: คำนวณจากตำแหน่งปลายทางหลัง Action สำเร็จ และระงับการเลือก Action ใหม่จน Animation เดินจบ

## 3. Collision Layers

ทุก Collider ต้องมี `occluder_type`, `surface_id` และข้อมูลเจ้าของชิ้นส่วน ห้ามอนุมานชนิดจากชื่อ Node

| ชนิด | บังการเดิน | รองรับน้ำหนัก | บังสายตา/กระสุน | หมายเหตุ |
|---|---:|---:|---:|---|
| `FLOOR` | ไม่บังแนวราบ | ใช่ | ใช่ | เป็นแผ่นทึบสองด้าน พื้นที่ Opening ต้องถูกตัดออกจริง |
| `WALL` | ใช่ | ไม่ | ใช่ | ทึบเต็มความสูงที่กำหนด |
| `STAIR` | ไม่บังตามแนวเดิน | ใช่ | ใช่ | ใช้ Mesh/Collision รูปลิ่มหรือขั้นจริง ไม่ใช้กล่องเต็มพื้นที่ |
| `RAMP` | ไม่บังตามแนวเดิน | ใช่ | ใช่ | ใช้ผิวลาดจริง |
| `RAILING` | ใช่ | ไม่ | บังเป็นราย Ray | ใช้สร้าง Cover แต่ไม่ทำให้เป้าหมายหายอัตโนมัติ |
| `DOOR` | ตามสถานะ | ไม่ | ตามสถานะ | เปิด = ปิด Collision, ปิด = ทำงานเหมือน Wall |
| `MOVEMENT_ONLY` | ใช่ | ไม่ | ไม่ | Invisible Wall ต้องไม่เข้าร่วม Visibility Query |
| `OPENING` | ไม่ใช่ Collider | ไม่ | ไม่ | เป็นการตัด Floor ไม่ใช่วัตถุ |
| `COMBATANT` | ใช้กับ Occupancy | ไม่ | ไม่ใน LOS ปกติ | ตัวละครอื่นไม่ทำให้เป้าหมายถูกซ่อน แต่อาจใช้กฎ Cover แยกภายหลัง |

Collision สำหรับการเดินและ Visibility แยก Mask กัน แต่สร้างจากข้อมูลแผนที่ชิ้นเดียวกัน

## 4. รูปร่าง Collision

- Floor ต้องสร้างจาก `walkable_rects - opening_rects`
- ภาพ Texture ยังคงแสดงเต็มตามงานภาพได้ แต่ไม่มีผลต่อ Collision
- Wall ใช้ Box ที่มีฐานและความสูงตรงกับข้อมูลแผนที่
- Stair/Ramp ใช้ TriMesh หรือ Convex Shape ที่ตรงกับความลาดจริง
- ห้ามใช้กล่องทึบครอบพื้นที่ใต้บันได เพราะตัวละครใต้บันไดต้องสามารถมองและเคลื่อนที่ในพื้นที่ว่างจริงได้
- Railing ต้องมีความสูงจริงและไม่ขยายลงไปถึงพื้นชั้นล่าง
- Collider ทุกชิ้นต้องเปิด Debug View ได้

## 5. Visibility Query

API หลักต้องมีรูปแบบเทียบเท่า:

```text
query_visibility(observer, target) -> VisibilityResult
```

`VisibilityResult` ต้องประกอบด้วย:

- `state`: `VISIBLE`, `PARTIAL` หรือ `HIDDEN`
- `clear_samples`: จำนวน Ray ที่ผ่าน
- `total_samples`: จำนวน Ray ทั้งหมด
- `cover`: `NONE`, `LIGHT`, `HEAVY` หรือ `TOTAL`
- `blocked_samples`: รายการจุดเป้าหมาย Collider ที่ชน และตำแหน่งชน
- `observer_position` และตำแหน่ง Sample ของเป้าหมายที่ใช้จริง

ห้ามคืนค่าเพียง Boolean เพราะ UI, Cover และ Debug ต้องทราบสาเหตุ

## 6. จุดเริ่มและจุดเป้าหมายของ Ray

จุดเริ่มมีจุดเดียวที่ระดับตาของผู้มอง:

```text
eye = observer.world_position + observer.eye_offset
```

เป้าหมายมี 3 จุด:

- `head`: ประมาณ 90% ของความสูงตัวละคร
- `chest`: ประมาณ 60% ของความสูงตัวละคร
- `pelvis`: ประมาณ 35% ของความสูงตัวละคร

ความสูงและ `eye_offset` ต้องอยู่ในข้อมูล Combatant ไม่เขียนเลข `+5.0` กระจายตามโค้ด

ก่อนยิง Ray ให้เลื่อนต้นและปลายเข้าหากันด้วย Epsilon เล็กน้อย เพื่อไม่ให้ชนพื้นหรือ Collider ที่รองรับตัวละครตรงจุดกำเนิด/ปลายทางโดยผิดพลาด

## 7. การแปลผล

| Ray ที่ผ่าน | Visibility | Cover เริ่มต้น | เลือกเป็นเป้าหมาย |
|---:|---|---|---:|
| 3/3 | `VISIBLE` | `NONE` | ได้ |
| 2/3 | `VISIBLE` | `LIGHT` | ได้ |
| 1/3 | `PARTIAL` | `HEAVY` | ได้ แต่รับโทษตามระบบต่อสู้ |
| 0/3 | `HIDDEN` | `TOTAL` | ไม่ได้ |

ข้อยกเว้นต้องมาจาก Ability/Status เช่น True Sight หรือ Search เท่านั้น ห้ามเพิ่มข้อยกเว้นตามชั้นหรือชนิดแผนที่

## 8. กฎการชน Ray

1. Ray ใช้ Visibility Mask เท่านั้น
2. Ray ชน `WALL`, `FLOOR`, `STAIR`, `RAMP` หรือประตูปิดก่อนถึง Sample ถือว่า Sample นั้นถูกบัง
3. Ray ชน `RAILING` ถือว่า Sample นั้นถูกบังและบันทึกเป็น Cover
4. Ray ไม่สนใจ `MOVEMENT_ONLY`, ภาพ Texture, Fog, Camera Cutaway และ Combatant อื่น
5. Collider ที่รองรับผู้มองหรือเป้าหมายถูกละเว้นเฉพาะการชนที่อยู่ภายใน Epsilon ของต้นหรือปลาย Ray เท่านั้น ห้ามละเว้น Collider ทั้งชิ้น
6. ไม่มีกฎ “อยู่ชั้นเดียวกันให้มองผ่าน Floor”
7. ไม่มีกฎ “คนละชั้นต้องผ่าน N เส้น” การแปลผลใช้ตารางเดียวกันทุกกรณี
8. `surface_id` ใช้สำหรับ Navigation, การเลือกชั้น และข้อมูล UI ไม่ใช้ตัดสินว่า Ray ควรผ่านวัตถุหรือไม่

## 9. กฎเฉพาะพื้นที่หลายระดับ

### ใต้บันได

- ถ้า Ray อยู่ในช่องว่างใต้ Mesh บันได ต้องผ่าน
- ถ้า Ray ตัดผิวบันได ต้องถูกบัง
- ตัวละครสองตัวใต้บันไดมองเห็นกันเมื่อไม่มี Wall หรือผิวบันไดคั่นจริง

### บนบันได

- ตำแหน่งและความสูงเปลี่ยนต่อเนื่องตาม Ramp
- ห้ามกระโดด `elevation_feet` จากชั้นล่างเป็นชั้นบนทันทีในระหว่างการคำนวณตำแหน่งบน Ramp
- Ray ใช้ความสูง ณ จุดปัจจุบันบน Ramp

### ช่องเปิด

- Opening ไม่มี Collider
- Ray ผ่านช่องเปิดขึ้นหรือลงได้
- ขอบพื้นรอบ Opening ยังคงบังตามรูปทรงจริง

### ระเบียงและราว

- Floor ระเบียงบังการมองจากด้านล่างเมื่อ Ray ตัดพื้น
- Railing บังเฉพาะ Sample ที่ Ray ชน
- การผลักตกและการเดินใช้ข้อมูลขอบ/ราวชุดเดียวกัน แต่เป็นคนละ Query

## 10. ผู้ใช้ผลลัพธ์

ทุกระบบต่อไปนี้ต้องเรียก Visibility Service เดียวกัน ห้ามยิง Raycast เอง:

- การแสดงหรือซ่อนศัตรู
- การเลือกศัตรูด้วยเมาส์
- Target Panel และข้อความ Visibility
- Attack, Ability, Skill และ Item ที่ต้องใช้ LOS
- AI เลือกเป้าหมายและตัดสินใจค้นหา
- Reaction และ Opportunity Attack
- Cover และ Attack Penalty
- Combat Preview และเส้นเล็ง

ฝ่ายเดียวกันแสดงได้เสมอเพื่อความสะดวกในการควบคุม แต่การโจมตีหรือช่วยเหลือที่กำหนดว่าต้องมี LOS ยังต้องเรียก Query ตามกติกา

## 11. สิ่งที่ไม่ใช่ Visibility Rule

- ชั้นที่เลือกดูมีผลเฉพาะ Render และการคลิกพื้น
- Camera Cutaway มีผลเฉพาะการอ่านภาพของผู้เล่น
- Fog of War หากเพิ่มภายหลัง มีผลเฉพาะพื้นที่เคยสำรวจ
- การมองเห็น Token ของฝ่ายเดียวกันเป็นกฎ UI
- สิ่งเหล่านี้ห้ามเปลี่ยนผล `VisibilityResult`

## 12. Debug Mode ที่บังคับต้องมี

เมื่อเปิด Visibility Debug:

- วาด Ray สีเขียวสำหรับเส้นที่ผ่าน
- วาด Ray สีแดงถึงตำแหน่งชนสำหรับเส้นที่ถูกบัง
- แสดงชื่อ `occluder_type`, Node, `surface_id` และระยะชน
- แสดง Eye/Head/Chest/Pelvis เป็นจุดคนละสี
- แสดงผลรวม เช่น `PARTIAL 1/3 - blocked by StairRamp`
- เลือก Combatant สองตัวเพื่อทดสอบ Query ได้โดยไม่ต้องเริ่ม Turn

## 13. Acceptance Tests

ระบบใหม่ต้องผ่านอย่างน้อยกรณีต่อไปนี้:

1. ห้องโล่งชั้นเดียวกัน: เห็น 3/3
2. กำแพงทึบคั่น: ซ่อน 0/3
3. โผล่ศีรษะเหนือกำแพงเตี้ย: Partial
4. Invisible Wall คั่น: ยังมองเห็น แต่เดินผ่านไม่ได้
5. สองตัวอยู่ใต้บันไดโดยไม่มีผิวคั่น: มองเห็น
6. ตัวหนึ่งใต้บันได อีกตัวอยู่บนผิวบันได: พื้นบันไดบังตาม Ray จริง
7. มองผ่าน Opening ขึ้นชั้นบน: มองเห็นเมื่อ Ray ผ่านช่อง
8. พื้นชั้นบนคั่นโดยไม่มี Opening: ซ่อน
9. Railing บังหนึ่ง Sample: Partial หรือ Visible พร้อม Cover ตามจำนวน Ray
10. ประตูเปิด: มองเห็น และประตูปิด: ถูกบัง
11. เปลี่ยนชั้นที่แสดงใน UI: ผล Query ไม่เปลี่ยน
12. Camera Cutaway เปิด/ปิด: ผล Query ไม่เปลี่ยน
13. ศัตรูที่เปลี่ยนจาก Visible เป็น Hidden: Token และ Target Panel ถูกล้างในเฟรมเดียวกัน
14. AI, Attack Preview และ Attack Execution ให้ผล Visibility ตรงกัน

## 14. ขอบเขตการรื้อระบบเดิม

ต้องนำออกหลังระบบใหม่เชื่อมครบ:

- เงา Polygon/Visibility Fan สำหรับ Combat
- กฎ Same Surface ที่ละเว้น Floor ทั้งชิ้น
- กฎจำนวน Ray ต่างกันตามชั้น
- Raycast แบบจุดเดียว `position + Vector3.UP * 5.0`
- LOS แบบ 2D สำหรับ Building Map
- การตรวจ Visibility ซ้ำใน UI, AI หรือ Ability แต่ละระบบ

ระบบ Combat ที่ไม่เกี่ยวกับตำแหน่ง เช่น Turn, AP, Damage, Status และ Inventory ไม่ต้องรื้อ
